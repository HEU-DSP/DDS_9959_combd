## 1. 总览：一套代码，两条腿，当前跑的是降级那条

整个仓库围绕一个编译开关分成两条互斥的传输路径：

```c
/* App/phase1_config.h:28 */
#define AD9959_DOWNGRADE_MODE  1      /* ← 当前值 */
```


| 维度               | 降级模式（`=1`，**当前编译**）             | DMA 模式（`=0`，目标架构）                      |
| :------------------- | :------------------------------------------- | :------------------------------------------------ |
| 时基               | TIM8 自由运行 10 kHz 中断                  | LPTIM3 → DMAMUX 同步门                         |
| 发送               | ISR 内**阻塞** `HAL_SPI_Transmit` ×4/通道 | SPI1 DMA，硬件自动                              |
| 帧存放             | `pre_encoded[4]`（DTCM，结构体数组）       | `tx_bank[2].spi1[]`（D2 SRAM，扁平）            |
| ISR 负担           | 生成符号 + 编码 + 4 次阻塞发送             | `TxBuf_Swap()` + 重装 DMA（约 10 行）           |
| `trigger.c` 触发链 | **编译进去但完全不可达**                   | 全部生效                                        |
| IO_UPDATE          | TIM8_CH1 PWM（PC6），每周期自动            | 同左，但由 LPTIM3_OUT 经 ETR 复位 TIM8 重新对齐 |

> ⚠️ **这是理解本仓库的第一前提**。`Drivers/Trigger/trigger.c` 全部 126 行、`main.c:186-215` 的 `HAL_SPI_TxCpltCallback`、`dds_control.c` 的 DMA 分支，全部被 `#if` 关在编译门槛外。

> 链接 map 独立验证：`Trigger_Start`、`Encoder_Encode1Bit_Direct` 只出现在 map 第 60–2605 行的 `Discarded input sections` 段（被 `--gc-sections` 回收）；`Encoder_BuildBank_DMA` 连 `.o` 都没进。**读代码时不要顺着 `trigger.c` 去理解现状。**

## 3. App 层：控制面

### 3.1 上位机协议（`host_protocol.c` / `host_protocol.h`）

帧格式：`SOF1(0xA5) SOF2(0x5A) VER(0x01) SEQ CMD LEN_L LEN_H`（7 B 头）+ PAYLOAD（≤64 B）+ CRC16（2 B，CRC-16/CCITT-FALSE，多项式 0x1021，初值 0xFFFF，覆盖 VER..PAYLOAD，不含 SOF）。

`HostProtocol_Task()` 在主循环运行，通过 `parse_byte()` 状态机（`host_protocol.c:414-475`）逐字节喂入，完成后 `frame_dispatch()` 分派。


| CMD           | 值   | 写入目标                                        |
| :-------------- | :----- | :------------------------------------------------ |
| `PING`        | 0x00 | 只读，回 4 B 版本                               |
| `GET_STATUS`  | 0x01 | 只读，回 3 B/通道                               |
| `SET_CW`      | 0x02 | `pending_cfg[ch].cw.{ftw,asf}`                  |
| `SET_FSK`     | 0x03 | `.fsk.{ftw_mark,ftw_space,asf}`                 |
| `SET_ASK`     | 0x04 | `.ask.{ftw,asf_on,asf_off}`                     |
| `SET_BPSK`    | 0x05 | `.bpsk.{ftw,asf,phase0,phase1}`                 |
| `SET_QPSK`    | 0x06 | `.qpsk.*`（四相位**硬编码**，不可由上位机指定） |
| `SET_4FSK`    | 0x07 | `.fsk4.{ftw[0..3],asf}`                         |
| `SET_SYMBOLS` | 0x08 | **直接写 `sym_buf`，绕过 `pending_cfg`**        |
| `APPLY`       | 0x09 | 触发`DDSControl_RequestApply()`                 |
| `STOP_OUTPUT` | 0x0A | 触发`DDSControl_RequestStop()`                  |
| `GET_DIAG`    | 0x0B | 只读，回 7×u32                                 |

NACK 通过 `cmd | 0x80` 回显，原因码见 `host_protocol.h:55-62`。

**核心设计**：`SET_*` 只写 **`pending_cfg[]` 暂存区**（定义在 `dds_control.c:35-36`），不碰运行中的 `mod_cfg[]`。必须再发 `APPLY` 才原子生效——这是避免在发送过程中改配置的关键。

> ⚠️ `SET_SYMBOLS` 是唯一的例外：它直接写 `sym_buf`，不经暂存也不参与 APPLY。
>
> ⚠️ 只有 `SET_CW` 做了 ASF 范围检查（`host_protocol.c:212`）；FSK/ASK/BPSK/QPSK/4FSK 只校验最小长度。`frame_ver` 被锁存但从不与 `HOST_VER` 比对。
>
> ⚠️ 收到 `len > 64` 时静默重新同步，不回 NACK（`host_protocol.c:442-445`）。

### 3.2 APPLY 安全切换（`dds_control.c`）

`DDSControl_Task()` 是受 `busy` 保护的状态机，**STOP 优先于 APPLY**。

**降级模式 APPLY**（`dds_control.c:170-202`）：

```
1. TIM8->DIER &= ~TIM_IT_UPDATE     停中断，但计数器与 CH1 PWM 继续运行
2. 自旋等 ds.tim8_isr_active == 0   等在飞的 ISR 排空
3. 查 HAL_SPI_GetState() == READY   否则回滚 DIER 并返回 ERR_SPI
4. dds_apply_config():
     AD9959_IOUpdateGpioInit()      PC6 借为 GPIO
     memcpy(pending_cfg → mod_cfg) ×4
     Encoder_WriteStaticRegs(mask)  CSR + CFR
     CW 通道预置 CFTW + ACR
     AD9959_IOUpdate()              软件脉冲
     AD9959_IOUpdateTimerInit()     PC6 还给 TIM8_CH1 AF
5. SymbolBuf_Clear(); Encoder_BuildBank()
6. TIM8->DIER 恢复，tx_running = 1
```

**DMA 模式 APPLY**（`dds_control.c:204-234`）：第 1–3 步换成 `Trigger_Stop()` + 有界轮询（10000 次迭代，非定时），第 5 步改为重建**两个 bank** 并各 `TxBuf_Swap()` 一次，第 6 步换成 `Trigger_Restart()`。

**设计意图**：APPLY 全程不碰 REF_CLK、595、PLL、MASTER_RESET——只动 CSR/CFR/CFTW/ACR/POW。

> ⚠️ `dds_apply_config()` **无条件返回 `DDS_APPLY_OK`**（`dds_control.c:152`）；`AD9959_WriteRegister` 的 SPI 失败只记录在 `ad9959_hwspi_debug` 中，不会传播为 NACK。
>
> ⚠️ APPLY 的 ACK 在真正执行**之前**发出（`host_protocol.c:346-354`）。
>
> ⚠️ 降级分支保存并恢复的 `TIM8->ARR/CCR1` 全程无人修改，是死代码；真正起暂停作用的只有 `DIER` 屏蔽。
>
> ⚠️ `dds_control.h:30` 的 `DDS_APPLY_ERR_TIM` 从未被任何路径返回。

### 3.3 调制数学（`channel_config.c: build_channel_command()`）

全仓库**唯一活跃的调制实现**（历史上的 `mod_*.c` 一整套已随 FrameBuilder 死树于 2026-08-08 删除）。输入 `ModInput`，输出 `DDS_Command{ftw, asf, pow, profile}`。


| 模式 | FTW                                              | ASF                           | POW                     | 备注                          |
| :----- | :------------------------------------------------- | :------------------------------ | :------------------------ | :------------------------------ |
| CW   | `cw.ftw`                                         | `cw.asf`                      | 0                       |                               |
| FSK  | `bit ? ftw_mark : ftw_space`                     | `fsk.asf`                     | —                      |                               |
| ASK  | `ask.ftw`                                        | `bit ? asf_on : asf_off`      | —                      |                               |
| GFSK | `center + state`，`state = (state*3 + target)/4` | `gfsk.asf`                    | —                      | 1 阶 IIR，α=¼，int64 中间量 |
| MSK  | `center + dev*cos_val/0x2000`                    | `msk.asf`                     | —                      | ⚠️ 实际未使用数据位         |
| QPSK | `qpsk.ftw`                                       | `qpsk.asf`                    | 查表`symbol & 3`        |                               |
| 4FSK | `fsk4.ftw[symbol & 3]`                           | `fsk4.asf`                    | —                      |                               |
| AM   | `am.ftw`                                         | `center + delta*sample/32767` | —                      | ⚠️ sample 恒 ±32767        |
| FM   | `center + dev*sample/32767`                      | `fm.asf`                      | —                      | ⚠️ 同上                     |
| BPSK | `bpsk.ftw`                                       | `bpsk.asf`                    | `bit ? phase1 : phase0` |                               |

**输入宽度**：`mode_input_bits()` 给出每模式所需位数——FSK/ASK/GFSK/MSK/AM/FM/BPSK → 1；QPSK/4FSK → 2；CW/OFF → 0。`enabled_input_bits()` 对所有使能通道取最大值。

> ⚠️ GFSK 的 `filter_state` 与 MSK 的 `phase_acc` 是**带状态**的，会被 `build_channel_command()` 就地写回 `mod_cfg[]`。降级模式下该函数运行在 TIM8 ISR 中，而主循环可能同时 `memcpy` 整个 `mod_cfg`（`host_protocol.c:68` 的 `debug_snapshot`）。目前**仅靠 DIER 屏蔽**保证安全。
>
> ⚠️ `main.c:144-154` 与 `main.c:432-442` 各自内联复制了一份 `enabled_input_bits()` 的逻辑（因为 `channel_config.c` 里的版本是 `static`）。**同一份 mode→bits 映射在仓库里存在三份副本。**

### 3.4 乒乓缓冲与时序（`tx_buffer.c`）

```c
typedef struct { uint8_t spi1[64]; uint8_t spi3[64]; } FrameBank;   /* tx_buffer.h:26-29 */
FrameBank tx_bank[2] __attribute__((section(".dma_buffer"), aligned(32)));
volatile uint8_t  tx_active;      /* 0/1，TxBuf_Swap() 翻转 */
volatile uint16_t tx_bank_bytes;  /* ISR 读 / 主循环写 */
```

- `TxBuf_GetIdle()` → `&tx_bank[tx_active ^ 1]`；`TxBuf_GetActive()` → `&tx_bank[tx_active]`。
- 三者均为 `static inline`，**无锁无原子**。`TxBuf_Swap()` 在 DMA 完成 ISR 与主循环中都会被调用。
- `FrameBank.spi3[]` **从未被写入**——2-bit 双线模式推迟，`BSP_SPI_Both_DMA_Start()` 直接丢弃 `spi3_buf` 参数（`bsp_spi.c:77`）。
- `.dma_buffer` 段映射到 **RAM_D2（0x30000000）**，绕过 DTCM，供 DMA1 访问；MPU 配置为 Non-Cacheable。
- `TxTiming_Update()` 只做 `sample_rate = baud_rate * samples_per_sym`，无除零/溢出保护。

## 4. Middleware 层：帧生成

### 4.1 14 字节帧格式（`dds_encoder.c`）

一个通道一帧，布局固定，`ENCODER_FRAME_FLAT_BYTES = 14`：


| 偏移 | 长度 | 内容                                               | 指令字节 |
| :----- | :----- | :--------------------------------------------------- | :--------- |
| 0    | 2    | CSR：`reg & 0x7F`，通道使能掩码 `1 << (ch+4)`      | `0x00`   |
| 2    | 5    | CFTW：`0x04` + FTW[31:24]…[7:0]（大端）           | `0x04`   |
| 7    | 4    | ACR：`0x06`, `0x00`, `0x10 | asf>>8`, `asf & 0xFF` | `0x06`   |
| 11   | 3    | CPOW：`0x05`, `(pow>>8) & 0x3F`, `pow & 0xFF`      | `0x05`   |

合计 14 B；4 通道 = 56 B ≤ `FRAME_BUF_SIZE(64)`。

- **CSR 每帧都要重发**——AD9959 会保留上一次的 CSR 通道选择，不是冗余（`dds_encoder.c:91-93`）。
- ACR 的 24 位值 = `0x001000 | (asf & 0x3FF)`：bit12 = `AMP_MULT_ENABLE`，bit[9:0] = ASF。斜坡率恒 0，自动斜坡与 IO_UPDATE 加载位从不设置。
- CPOW 只取低 14 位（`& 0x3F` / `& 0xFF`）。
- 寄存器顺序为 CSR → CFTW → ACR → CPOW，与 datasheet 地址序（CFTW 0x04 / CPOW 0x05 / ACR 0x06）不同，是历史选择。

### 4.2 两个编码入口


|          | `Encoder_Encode1Bit()`                                        | `Encoder_Encode1Bit_Direct()`          |
| :--------- | :-------------------------------------------------------------- | :--------------------------------------- |
| 声明     | `dds_encoder.h:63`                                            | `dds_encoder.h:77`                     |
| 输出     | `DDS_EncodedFrame`（`csr[2] cftw[5] acr[4] cpow[3]`，结构体） | 扁平`uint8_t*`                         |
| 字节内容 | **完全相同**（结构体为 14 B 无 padding，顺序一致）            |                                        |
| 索引方式 | 具名字段                                                      | 累加偏移`off` 0→2→7→11→14          |
| 用途     | 降级模式 →`pre_encoded[]`                                    | DMA 零拷贝 →`TxBuf_GetIdle()->spi1[]` |
| 当前状态 | **活跃**                                                      | 编译进去但被 gc-sections 丢弃          |

对应的两个 bank 构建入口（共用 `build_channel_command()`，调制数学只有一份）：


|        | `Encoder_BuildBank()`                    | `Encoder_BuildBank_DMA()`                                |
| :------- | :----------------------------------------- | :--------------------------------------------------------- |
| 声明   | `channel_config.h:30`，无条件编译        | `channel_config.h:39`，`#if !AD9959_DOWNGRADE_MODE` 包裹 |
| 目标   | `pre_encoded[DDS_CHANNEL_COUNT]`（DTCM） | `TxBuf_GetIdle()->spi1[]`（D2 SRAM）                     |
| 返回   | `bool`（≥1 通道成功）                   | `uint16_t` 总字节数（无通道则为 0）                      |
| 副作用 | 更新`pre_encoded_mask`                   | 更新`tx_bank_bytes`，并将缓冲区剩余部分补零              |

> ⚠️ **符号读取失败会整帧丢弃**：`channel_config.c:227-229` 在 `SymbolBuf_ReadBits()` 失败时直接 `return false`，**连不需要符号的 CW 通道也一起丢掉**，`pre_encoded_mask` 保持 0。DMA 模式下返回 0 → `tx_bank_bytes = 0` → `HAL_SPI_TxCpltCallback` 拒绝重装（`main.c:202-204`），链条**静默停摆**而 LPTIM3/TIM8 照常运行。

### 4.3 符号源与缓冲区

**`SymbolSource_Generate(uint8_t input_bits)`**（`symbol_source.c:28-68`）目前是**测试桩**，不是真正的数据映射：

- `input_bits == 1` → 输出 0/1 交替（`toggle_bit ^= 1`）
- `input_bits == 2` → 循环 4 个 Gray 码符号
- `input_bits == 0` → 直接返回（CW 不需要符号）
- `sine32[32]` 与 `sine_idx` 只被 `(void)` 引用，**从未使用**

**`sym_buf`**（`symbol_buffer.c`）是 App 与 Middleware 之间**唯一跨上下文对象**：

- 容量 256 个元素，**每元素 1 bit**（`sym_buf.data[i] = bits[i] & 0x01U`，`symbol_buffer.c:27`）
- 靠 `volatile bool ready` / `free` 两个标志做 SPSC 握手，**无锁无原子、无临界区**
- 降级模式：读端在 TIM8 ISR、写端在主循环；DMA 模式：两端都在主循环
- `bits_per_sym` 字段被三处赋予不同语义（`symbol_buffer.h:23`、`symbol_source.h:27`、`symbol_source.c`），且**恒被写为 1**，从不被 `ReadBits` 使用——是只写状态

### 4.4 FTW 计算（`dds_calc.h`）

`DDSCalc_FTW(freq_hz)` 为 `static inline`，Q32.32 乘移定点：

```
SCALE = ceil(2^64 / 490909091) = 0x8_BFBEF3D4
q   = (freq << 3) + hi32(freq * 0xBFBEF3D4)        /* 一次移位 + 一次 UMULL */
rem = (freq << 32) - q * SYSCLK
FTW = q + (2*rem >= SYSCLK ? 1 : 0)                /* round-half-up */
```

- 精确性依赖 Granlund 条件 `(-2^64) mod SYSCLK = 33784828 < 2^32`，目前只在注释中断言，**无 `static_assert`**。
- 编译期常量会被 GCC 直接折叠为零开销；运行时（host SET 命令）为 3× UMULL + 比较。
- 相比 2026-08-08 之前的 64 位软件除法，host SET 路径从约 100+ 周期降到 3 条 UMULL 指令。

## 5. 底层 SPI 发送

### 5.1 当前生效路径：降级模式

`main.c:134-184`，TIM8 @ 10 kHz 自由运行中断：

```c
ds.tim8_isr_active = 1U;                    /* 与 APPLY 的握手标志 */
if (!SymbolBuf_HasData() && SymbolBuf_IsFree())
    SymbolSource_Generate(ib);              /* ib 由内联扫描 mod_cfg[] 得出 */
(void)Encoder_BuildBank();                  /* → pre_encoded[] + pre_encoded_mask */

for (ch = 0; ch < DDS_CHANNEL_COUNT; ch++) {
    if (!(pre_encoded_mask & (1U << ch))) continue;
    const DDS_EncodedFrame *f = &pre_encoded[ch];
    HAL_SPI_Transmit(&hspi1, f->csr,  2, HAL_MAX_DELAY);   /* 每寄存器独立 CS 帧 */
    HAL_SPI_Transmit(&hspi1, f->cftw, 5, HAL_MAX_DELAY);
    HAL_SPI_Transmit(&hspi1, f->acr,  4, HAL_MAX_DELAY);
    HAL_SPI_Transmit(&hspi1, f->cpow, 3, HAL_MAX_DELAY);
}
ds.tim8_isr_active = 0U;
```

**IO_UPDATE 由 TIM8_CH1 硬件 PWM（PC6）在每个周期自动产生**，因此本周期写入的数据由**下个周期**的 IO_UPDATE 生效——一拍流水，对 CW 与连续相位调制透明。

> ⚠️ 该 ISR 同时承担符号生成、调制计算、编码和 8 次阻塞 SPI 发送（4 通道 × 4 段），与分层规范"ISR 只置标志/短搬运"相悖。10 kHz 是降级规避值，不是目标方案。

### 5.2 目标路径：DMA 模式（当前不可达）

```
LPTIM3 (PA1 = OUT, 135 MHz / DIV1, ARR = 1349 → 10 kHz)
  │
  ├─(1)→ DMAMUX 同步门 (DMA1_Stream1 / SPI1_TX)
  │        SyncSignal = HAL_DMAMUX1_SYNC_LPTIM3_OUT, SyncPolarity = RISING
  │        RequestNumber = 14 (ENCODER_FRAME_FLAT_BYTES)
  │        └─→ SPI1 DMA 从 tx_bank[active].spi1 搬 14 B
  │              └─→ PA15 (CS) / PB3 (SCLK) / PD7 (MOSI, SDIO0)
  │
  ├─(2)→ 飞线 PA1 → PA0 (TIM8_ETR) → TIM8 Slave Reset
  │        └─→ CH1 PWM PC6 = IO_UPDATE   (CCR1 = P1_CH1_DELAY)
  │        └─→ CH2 PWM PC7 = DIO3        (CCR2 = P1_CH2_DELAY)
  │
  └─(3)→ 飞线 PA1 → PE0 (TIM4_ETR) → TIM4 Slave Reset
           └─→ CH1/CH2 捕获 CS↓/CS↑ (PB6/PB7)，用于校准 CCR
```

**`RequestNumber = 14` 的由来**：DMAMUX 的 `NBREQ` 只有 5 位（最大 32），一次锁不住 56 B 整帧，所以按"一次脉冲 = 一个通道"切分，4 个脉冲构成一帧。CubeMX 生成的基线是 `RequestNumber = 1`，由 `trigger_setup_dmamux()` 在运行时改写（`trigger.c:33-47`）。

**DMA 完成中断**（`main.c:194-214`）只做 4 件事：

```c
TxBuf_Swap();
HAL_SPI_Transmit_DMA(&hspi1, TxBuf_GetActive()->spi1, tx_bank_bytes);
ds.frame_count++; ad9959_diag.spi1_done_count++;
ds.dma_bank_ready = 1U;      /* 通知主循环填充 idle bank */
```

> ⚠️ `Trigger_Init()` 是否成功无法由返回值判断（`void`），且 `trig_cfg.bank_size` 缓存后从未使用。
>
> ⚠️ `Trigger_Start()` 使用 `trig_cfg.spi1_ping`（在 `Init` 时抓取的 `tx_bank[0].spi1` 指针），任何重建 bank 的 APPLY 之后该指针语义已陈旧；只有字节数会被刷新。
>
> ⚠️ `Trigger_Restart()` 不重新配置 DMAMUX、不重设 TIM8 延迟，只在 `Trigger_Stop()` 之后有效，且**不轮询 SPI 状态**。
>
> ⚠️ DMA 模式 APPLY 在 `Encoder_BuildBank_DMA()` 返回 0 时仍会 `Trigger_Restart()`，造成"定时器在跑、数据通路为 0 字节、`tx_running = 1`"。

### 5.3 CS 与时钟

- **CS = SPI1 硬件 NSS（PA15）**，`SPI_NSS_HARD_OUTPUT`（SSOE）。**BSP 层没有任何软件 CS 控制。**
- CS 在整段 HAL 传输期间保持有效，抬起是 `HAL_SPI` 传输结束时 `__HAL_SPI_DISABLE()` 的副作用（SPE=0 释放 SSOE）。
- ⚠️ **`SPI_CFG2_SSOM` 必须在 `MX_SPI1_Init` 的 USER CODE 段清除**（`main.c:867`）。CubeMX 默认 `NSS_PULSE_ENABLE` 会在字节间抬 CS，直接打断 AD9959 的多字节寄存器写（CFTW 5 B、ACR 4 B）——这是历史 commit "传输稳定但是没波" 的最可能根因。
- `main.c:862` 额外设置 `SPI_CFG2_AFCNTR`，使 MOSI/SCK 在两次突发之间保持驱动。
- **SPI1 SCK = 125 MHz**（PLL2 250 MHz 内核 ÷2 预分频），8-bit，每字节 64 ns，单通道 14 B ≈ 896 ns。

### 5.4 BSP 封装的实际形态（`bsp_spi.c`）

接口签名看着通用，实际**只认 SPI1**——每个入口都有 `if (spi != SPI1) return;`。


| 函数                                          | 形态                                                                                                                           |
| :---------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------- |
| `BSP_SPI_Transmit` / `BSP_SPI_TransmitStatus` | 阻塞，`HAL_MAX_DELAY`；size 0 静默丢弃                                                                                         |
| `BSP_SPI_DMA_Start`                           | `HAL_SPI_Transmit_DMA` + 记录 `ad9959_diag`                                                                                    |
| `BSP_SPI_Abort` / `Abort_IT`                  | 调`HAL_SPI_Abort[_IT]`                                                                                                         |
| `BSP_SPI_Both_DMA_Start`                      | ⚠️ "Both" 是历史命名，**`spi3_buf` 参数被 `(void)` 丢弃**；返回 `void`，遇 `HAL_BUSY` **静默返回**，调用方无法区分成功与被拒 |
| `BSP_SPI_Both_Abort[_IT]`                     | 纯别名，只作用于 SPI1                                                                                                          |

> ⚠️ **本模块没有任何状态机**——没有 busy 标志、没有队列、没有超时。"启动"就是 HAL 调用返回 OK，"停止"就是 Abort。所有时序保证都由调用方（Trigger 或 main.c）自行维持。

### 6.2 74HC595（2 片级联）

传输方式：**GPIO bit-bang**（非 USART10）。`HC595_Write()` MSB 先出，SHCP 上升沿移位，STCP 锁存。


| 片     | 帧位  | Q 脚   | 信号                                                                             |
| :------- | :------ | :------- | :--------------------------------------------------------------------------------- |
| #1 LED | 1–7  | Q1–Q7 | STBY / ANALOG READY / MOD READY / CH0–CH3 TRANSMIT（bit0 = NC）                 |
| #2 DDS | 9–14 | Q1–Q6 | 1.8VD / 1.8VA / master_reset / power_down / 3.3VD / clk_mode（bit8、bit15 = NC） |

> ⚠️ `hc595.c` 头注释声称走 "USART10 半双工单线"，实现是纯 GPIO 翻转；`BSP_USART10_Write()` 零调用者。
>
> ⚠️ `hc595.h:45-46` 声称"板上有混合信号极性"，但 `HC595_PackDDSControl()` 对所有 `true` 一律写 1，**没有反相逻辑**。

### 6.3 USART1 接收（`bsp_uart_rx.c`）

DMA1_Stream0 **循环模式**，`HAL_UARTEx_ReceiveToIdle_DMA(dmabuf, 256)`，**只启动一次，永不重启**（重启会导致 NDTR 卡在 255 的历史竞态）。IDLE 事件触发 `HAL_UARTEx_RxEventCallback`，按循环写指针增量拷贝到 128 B 环形缓冲，供 `HostProtocol_Task()` 逐字节取用。

> ⚠️ 若 256 B 内无 IDLE 事件且指针绕回相同位置，该批数据会被静默丢弃（`bsp_uart_rx.c:153` 提前返回）。
>
> ⚠️ `uart_rx_diag[4]` 在头文件中被声明但从未写入；`rx_overflow` 有写者无读取者。

## 8. 问题清单

### 8.1 🔴 会实际出错的

**1. 2-bit 符号路径越界读 + Gray 码被抹平**（`symbol_source.c:48,56`）

```c
uint8_t sym[1];              /* :48  只分配 1 字节 */
sym[0] = 0x03U;              /* :53  Gray "11" */
SymbolBuf_WriteBits(sym, 2U);/* :56  循环读 bits[1] → 栈越界读 */
```

且 `symbol_buffer.c:27` 写入时 `bits[i] & 0x01U`、`symbol_buffer.c:47` 读出时同样 `& 0x01U`——**两端都把值压成 1 位**，Gray 表的 `0x03`/`0x02` 永远退化为 `1`/`0`。结论：**QPSK 与 4FSK 的符号路径当前完全失效**，且伴随 UB 级的栈越界读。

**2. 符号不足会整帧丢弃**（`channel_config.c:227-229`、`269-271`）

`SymbolBuf_ReadBits()` 失败（缓冲余量 < 所需位数）时函数立即返回，**连不需要符号的 CW 通道一并丢弃**。DMA 模式下进一步导致 `tx_bank_bytes = 0`，链条静默停摆而定时器照跑。

**3. APB2 定时器时钟常量错误**（`bsp_tim.c:19`）

```c
#define BSP_TIM_APB2_TIM_HZ  281250000UL   /* 注释写 "SYSCLK/HPRE/D2PPRE2×2"，值却是错的 */
```

实际 `540 / 2 / 2 × 2 = 270 MHz`。影响：

- `BSP_TIM15_SetREFCLK(25e6)` 算得 divider = 11，真实输出 **24.545 MHz** 而非 25 MHz（REF_CLK 经 ×20 PLL 得 490.909 MHz，恰好与 `DDSCALC_AD9959_SYSCLK_HZ` 一致——**错得巧合而结果自洽**）。
- `P1_CH1_DELAY = 350` 的 tick 换算依据（"14 B × 64 ns ≈ 252 ticks @ 281.25 MHz"）偏差约 4%；实际应为 242 ticks @ 270 MHz。当前 350 仍 > 242，安全裕量尚在。

**4. `hspi3` 无定义**（`ad9959.c:30,593-598`）

`extern SPI_HandleTypeDef hspi3;` 在整个仓库无定义。`AD9959_Enable2BitSerial()` 目前仅靠 `--gc-sections` 回收才没暴露——**一旦被调用即链接失败**。

**5. `reply_send` 缺少 CRC 边界检查**（`host_protocol.c:117-119`）

`reply_add_u8()` 检查了 `rbuf_idx < HOST_FRAME_MAX(73)`，但 `reply_send()` 追加 2 字节 CRC 时无检查，而 `rbuf[73]` 正好是数组边界。目前最大回复（GET_DIAG 28 B）不可达，属**潜伏型溢出**。

## 11. 结论

仓库的**架构分层是清晰且基本落地的**：App 负责配置与安全切换、Middleware 负责调制数学与 14 字节帧、Bsp/Drivers 负责外设，`build_channel_command()` 与 `dds_encoder.c` 的职责边界干净，2026-08-08 的大清洗也确实清除了 FrameBuilder/mod_* 死树与重复实现。

但**运行态停留在降级模式**：目标触发链（LPTIM3 → DMAMUX → SPI1 DMA → TIM8 ETR）代码完整、文档齐全、`trigger.h` 注释也诚实标注了适用条件，却整体被 `AD9959_DOWNGRADE_MODE = 1` 关在编译门槛外并被链接器回收。真正的发送动作发生在 TIM8 的 10 kHz 中断里，由 4 次阻塞式 `HAL_SPI_Transmit` 完成。

**切换到 DMA 模式的最小路径**：`phase1_config.h` 改 0 → `make clean` → 重新编译烧录，并焊好 PA1→PA0、PA1→PE0 两根飞线。不需要改动任何驱动代码。

**建议的修复优先级**：

1. §8.1-1 2-bit 符号越界与 Gray 破损（真实 bug，影响 QPSK/4FSK 正确性）
2. §8.1-3 APB2 时钟常量（会改变 DDS 实际输出频率，需同步复核 `DDSCALC_AD9959_SYSCLK_HZ`）
3. §8.1-2 符号不足整帧丢弃（影响实时链路的鲁棒性）
4. §8.1-4 / §8.1-5 潜伏的链接失败与缓冲区溢出
5. §8.2-6 分层倒挂（架构清洁度，非阻塞）
